## PARA 结构

- `00-Inbox/`：临时捕获、未归类内容、开放问题。
- `10-Projects/`：有明确目标、结束条件、状态变化和后续动作的项目。
- `20-Areas/`：长期责任领域，没有自然结束点，需要维护标准。
- `30-Resources/`：文章、研究、外部资料、方法论和可复用参考。
- `40-Archives/`：完成、暂停、过期或不再活跃的内容。

## Agent 扩展

- `50-People/`：人、协作偏好、职责、沟通上下文。
- `60-Decisions/`：跨项目决策记录；项目内决策优先写项目笔记。
- `70-Playbooks/`：人类可读 SOP、复盘、操作手册；高频流程应提升为 Hermes skill。
- `90-Index/`：导航入口。
- `99-AI-Logs/`：只有有审计/诊断价值时才放 AI 日志，避免原始日志倾倒。

## 写入规则

1. 优先更新已有笔记，少创建重复笔记。
2. 看起来像项目但边界不清时，先问是否提升为 `10-Projects/`。
3. 文章/资料默认进 `30-Resources/`，不是项目。
4. 项目状态更新写项目笔记；领域健康/标准更新写 Area。
5. 保存笔记时：先写 Obsidian，再按需同步 Get笔记。

## Obsidian 使用建议

- 用 `[[双链]]` 连接项目、领域、资源和决策。
- Project note 应包含 Goal、Finish condition、Current status、Open loops、Next actions。
- Area note 应包含 Purpose、Maintenance standard、Current health/status、Active projects、Risks。

## 这期在讲什么

1. **从扑克到博弈论到推理的路径**：Noam Brown 先研究扑克，再研究博弈论与 Diplomacy（文明 Diplomacy AI），最后到 OpenAI 做推理方向。这条路径本身就说明**他的核心关切一直是"多智能体交互 + 不完美信息下的策略"**。
2. **核心指控是博弈论的根基假设错了**：博弈论的根基是"所有对手都理性，且这是共同知识"。但人**不理性**。用最后通牒博弈举例，理论最优解是给对方一分钱，对方当然会拒绝——而他们的 Diplomacy bot 恰恰表现出这种拒绝行为。他试过把"复仇感""公平感"编码进 bot，最后发现"太微妙了"。
3. **解法是放弃博弈论路线，转向在大量人类数据上训练"人类不理性模型"**，再让 AI 与这些模拟的人类交互、在真实人类环境里部署。原话："做超人级 Diplomacy AI 的真正方法，是在人类数据上训练，去理解人，而不是假设人是理性的。"
4. **关于 scaling 的关键洞察**：2022 年他离开 OpenAI 面别家时，几乎所有人都说"再预训练大几倍就好了"。他反驳说 GPT-4 下围棋要补上大约**六个数量级**的训练量，不现实。真正的洞察是：**模型必须先思考再行动**——2012/2013 年的扑克 bot 是瞬时出手的；后来发现模型思考越久表现越好，且用 RL 训练 chain-of-thought 比单纯 prompt 出的 CoT 好得多，这才让 test-time compute 能在语言模型上通用地 scaling。
5. **模型能力是"锯齿状"的**：AI 目前仍是人类能力的补充，人做模型擅长的部分、填补模型薄弱的部分。他举例模型实现 CFR 时会花几小时优化数值精度，但 CFR 本身对小误差非常鲁棒，数值根本不重要——**这暴露的是模型不擅长"发现自己在走错方向然后掉头"**。
6. **RLS（递归自我改进）不是新概念**：人类技术进步本身就是巨大的 RSI 循环。他认为真正的差异只有两点：**技术的通用性，以及速度**。当前瓶颈是算力，以及模型不擅长、必须靠人类的那条长尾。
7. **最有争议的一句话**：给有潜力的学生，最好的选择是直接退学去加入实验室。他说自己招过几个跳过大学最后一年的年轻人，表现都非常好。
8. **对 AGI 时间表**：认为未来一到两年仍会有非常陡峭的进步曲线。他不回避"给出下一个十年把寿命延长到 1200 到 1400 年"这种超级智能叙事。
9. **游戏中下一个真正的挑战**不是"让 AI 玩某个游戏"，而是"**把游戏当作通用 LLM 的评测集**"。他认为现在 LLM 还打不了实时策略游戏（"给他一年"）。
10. **关于扑克与诈唬**：他直言，如果 AI 五年后打 World Series of Poker，"如果它打的是 GTO，不会赢，因为这个游戏的方差太高"。但如果它能读人的脸来识别诈唬，它有机会做到超人级别，他给的胜率是 **20%**。

值得单独标出的两句金句：

> "要达到任何领域的顶尖，你需要极其优秀、极其勤奋，并且极其擅长钻研和练习。这是一项通用能力，可以迁移到扑克、交易，也可以迁移到 AI 研究。"

> "当人类从打孔卡过渡到编译器时，人的工作重心会转向计算机还做不好的事；再过渡到 LLM，又一次转移。今天的差别只是技术的通用性和速度，本质上并无不同。"

## 对我的系统/工作的启发

- **"锯齿状能力"是对 agent 产品最实用的一条设计约束**。模型不擅长"发现自己走错方向然后掉头"，意味着**多轮 agent 循环必须外挂方向校正机制**，不能指望模型自己察觉偏航。对 Hermes 而言，日报 cron 的"投递目标核对 / 链接逐条回溯 / 扫描器自检"本质上就是外挂的方向校正——今天 31 条链接逐条回溯 0 伪造，正是这条原则的落地形态。
- **"必须先思考再行动"是 test-time compute 能 scaling 的机制前提**，不是玄学。这直接支持 Hermes 的长任务设计：给 agent 更多思考预算（而不是更多并行调用）才是提升质量的杠杆。
- **RLS 的差异只在"通用性 + 速度"**——这个判断对"要不要自建 agent 循环"给了明确答案：自建的价值不在于更快，而在于**在特定工作流上更通用**（比如日报 cron 那些外部 API 编排、知识库写入、跨天状态维护，这是通用模型跑不出来的部分）。
- **"演示环境的能力不能外推到交付环境"**（与 11-26 Jordan Schneider 那期"机器人基本什么都做不了"同构）：今天早报 08:02 送达 ≠ 内容新鲜度合格（17.7 小时偏移），模型说"已投递" ≠ 用户看到的是当天的内容。**报告里必须把"送达"和"内容合格"分开数。**
